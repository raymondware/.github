# Contributing

Thanks for considering a contribution.

## Before starting

1. Read the repository README and any project-specific contributor or agent instructions.
2. Search existing issues and pull requests to avoid duplicate work.
3. For substantial behavior or API changes, open an issue before investing in an implementation.
4. Keep security reports private and follow `SECURITY.md`.

## Making a change

1. Fork the repository and create a focused branch.
2. Follow the project's existing structure, naming, and formatting conventions.
3. Add or update tests when behavior changes.
4. Update user-facing documentation when installation, configuration, commands, or output changes.
5. Run the repository's documented tests, linting, formatting, and build commands.
6. Keep the pull request limited to one coherent change.

## Pull requests

Include:

- What changed and why
- How the change was verified
- Screenshots or recordings for visible UI changes
- Compatibility or migration notes, when relevant
- Related issue numbers

Do not include secrets, private data, generated dependency folders, or unrelated cleanup.

## Documentation and examples

Examples should be runnable, narrowly scoped, and free of private paths or credentials. Confirm that copied material is compatible with the repository's license and include attribution where required.

## Review

A contribution may be declined when it falls outside the project's scope, duplicates existing behavior, introduces disproportionate maintenance cost, or cannot be verified. Constructive revisions are welcome.
